# The 4004 workshop: a circuit that runs a program

The Intel 4004 is one of the early microprocessors. It works with 4-bit data.
This workshop lets you study its arithmetic and control instructions in a
gate-level circuit. **It is not a full 4004 emulator, a transistor copy, or a
complete MCS-4 system.**

## Where do I open it?

**World → Example projects → Open 4004 workshop**. Your current world is kept;
the example opens as a new world. The circuit starts paused. You can step one
instruction at a time with **Clock cycle**, or run it continuously with **Run**.

Double-click the core module to go inside: you will see the registers and the
control module. Go into the control module too, and you can dig down into the
instruction decoder, the ALU, the register selectors, and the program counter
logic. Go back out with the path bar at the top (e.g. *4004 › Control and data path*) or with **Esc**. The minimap and Center help you move around a big circuit.

## What is actually running?

- Accumulator: **4 bits**.
- Carry: **1 bit**.
- R0–R15: **16 registers of 4 bits each**, kept in one 64-bit storage block.
- Program counter: **12 bits**, addressing a 4096-byte program ROM.
- Call returns: **three 12-bit addresses**, in a teaching-style shift stack.
- Instruction decoding, the ALU, register read/write selection, and the
  next-address calculation: **NAND gates and bus split/join parts**.

The built-in (Rust) models only do two things: the registers store data, and
the ROM reads a byte from its address. No Rust function reads an opcode or
does an addition or a branch. The logic is built on the board; if you change
the gates or the wires, the program behaves differently.

## Example program

The program ROM holds these hexadecimal bytes:

```
D0 B0 D3 F1 80 60 40 02
```

| Address | Instruction | Effect |
|---|---|---|
| 000 | LDM 0 | A=0 |
| 001 | XCH R0 | Swaps A and R0; R0 becomes 0 |
| 002 | LDM 3 | A=3 |
| 003 | CLC | C=0 |
| 004 | ADD R0 | A=A+R0+C; overflow goes to C |
| 005 | INC R0 | R0 goes up by one, wraps to 0 after 15 |
| 006 | JUN 002 | Loops back with a two-byte absolute jump |

After the first five cycles, PC should be 005 and A should be 3. In later
rounds, A changes depending on R0. The **A**, **C**, **PC**, **Instruction**,
and **ERROR** pins are watched from the start. Open the signal history and
follow the values.

## Instruction coverage

Families implemented in this version:

- NOP; LDM; LD, XCH; INC.
- ADD, SUB.
- FIM (load a constant into a register pair), FIN (indirect read from ROM), JIN.
- JCN, JUN, JMS, ISZ, BBL.
- CLB, CLC, IAC, CMC, CMA, RAL, RAR, TCC, DAC, TCS, STC, DAA, KBP.

**Not implemented yet:** SRC, DCL, and the `Ex` memory/I/O instructions
(WRM, RDM, WRR, etc.). When the circuit reaches one of these, or an opcode we
treat as unassigned, **ERROR=1** and the PC does not advance. They are not
silently treated like NOP. Some undocumented opcode behaviors of the original
hardware are also outside the scope of this workshop.

SUB works as `A + ~Rn + ~C`; the new C is the adder's carry output. Don't
confuse it with a "a borrow happened" bit. For short jumps at a page boundary,
what matters is the page reached after the instruction bytes are read; tests
keep this detail correct.

## Deliberate differences from the historical hardware

1. The real 4004 processes one instruction in eight or sixteen clock periods.
   Here, one rising edge runs one instruction, and two bytes can be read in
   parallel.
2. Instead of the real multiplexed, two-way 4-bit external bus, there are
   separate one-way buses.
3. The 4001/4002 support chips and the banked RAM/I/O system are not here yet.
4. The call stack is not a copy of the physical rotating address registers;
   it teaches three-level calls. Don't rely on its overflow behavior.
5. Electrical delays, PMOS transistors, and the silicon layout are not
   modeled. The layout on the board is a logic diagram.

## Experiments

1. In the ROM, change `D3` to `D7`. What does the loop add now?
2. Run IAC (`F2`) while A=15. What do you see in A and C?
3. Make Carry a **Stop on change** trigger. Catch the first overflow.
4. Open a module and cut one NAND connection. Does the bug only change how it
   looks, or does the result really change? Undo with Ctrl+Z.
5. Load `D5 40 00`. Why does A keep going back to 5?

## Sources and verification

- [4004 opcode table](https://pastraiser.com/cpu/i4004/i4004_opcodes.html):
  codes, instruction lengths, and timings.
- [MAME MCS-40 implementation](https://github.com/mamedev/mame/blob/master/src/devices/cpu/mcs40/mcs40.cpp):
  a cross-check, especially for SUB/DAC carry and page boundaries.

The project's tests check addition/subtraction combinations, accumulator
instructions, register pairs, branch boundaries, and that the example in the
ROM really runs on the circuit. This is not a full compatibility certificate
saying all historical software will run.
